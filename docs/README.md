# docs / 对外文档

本目录放**要发布的文档** —— 随仓库公开、供外部对接方依赖的那一类。

| 文件 | 内容 | 谁依赖它 |
|---|---|---|
| `PROTOCOL.md` | 对外协议正式契约（含变更记录） | 客户端、TUI 外包团队 |

> 目前只有 `PROTOCOL.md` 一份，**刻意不分子目录** —— 一个文件建目录是空架子，
> 等出现第二类文档（架构说明、配置参考、CLI 手册）再分，那时分类依据才清楚。

文件名用大写，与根目录的 `README.md` / `LICENSE` / `AGENTS.md` 一个体例：
一眼能看出是规范性文档，而不是随笔。

## 设计文档不在这里

设计稿、内部溯源材料、文档站产物在 **`design/`**，由 `.gitignore` 排除，
**只在本机可用、不随仓库发布**。

两个目录是刻意分开的，而不是「忽略 `docs/` 但开几个例外」：
后者的规则变成「不公开，除了某几个」，下一个人很容易把不该公开的放进例外。
现在的规则简单得多 —— **`docs/` 全公开，`design/` 全不公开**。
