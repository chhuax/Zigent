# 移植雷区 — 实现时必须逐字对齐的「雷」

> 本文件是 M0 spike 的**第一产出**。代码可以丢，这些约束不能丢。
> 每条都给出违反后果，作为实现时的硬约束。

---

## A. SSE 分帧（`sse.zig`）

| # | 约束 | 违反后果 |
|---|------|---------|
| A1 | **只在空行处提交事件**（空行 = 事件边界） | 事件被合并或丢失 |
| A2 | 多行 `data:` 用 **`\n` 拼接** | 报文被截断 |
| A3 | **流末尾没有空行时，最后一条事件也必须 flush**（EOF flush） | 丢最后一个事件（常见于 `message_stop` 前的 usage 帧） |
| A4 | 以 `:` 开头的是注释行，忽略 | 解析报错 |
| A5 | 字段值前**恰好一个**空格被剥离（`data: x` → `x`，`data:  x` → ` x`） | 文本开头多/少空格 |
| A6 | 行终止符 LF / CRLF / 裸 CR **都要认** | Windows 网关下解析失败 |
| A7 | **body reader 是分块的** —— 不能假设一次 `read()` = 一行 = 一个事件 | 随机丢帧（最难查的一类） |

**三家结束信号不同（最容易做错）**：

| provider | 结束方式 | 备注 |
|---|---|---|
| OpenAI Chat | `data: [DONE]` | 之后不再有数据 |
| Anthropic Messages | **没有 `[DONE]`**，靠 `message_stop` | 提前断流必须判为**可重试** |
| OpenAI Responses | `[DONE]` 是**错误信号** | 收到即抛 `RetriableException` |

**其它**：
- 提前断流的报错文案是契约的一部分：`"OpenAI stream closed before [DONE]"`、`"Anthropic stream closed before message_stop"`。
- **零事件的 200 响应**要单独识别，并把 `Content-Type` 打出来（否则拿到 HTML 错误页时无从诊断）。
- **取消路径必须静默**（取消导致的 onClose 不得报错）。
- **空闲看门狗 90s**（env `agent.stream.idleTimeoutSeconds`）。关键：**provider 的 keepalive/`ping` 帧只触发 `onStreamActivity()`，不算 `onPartial*`** —— 心跳不能只在自己解析文本的地方算。

## B. tool_call 增量拼接（`toolcalls.zig`）—— 三家三套语义

| | OpenAI Chat Completions | Anthropic Messages | OpenAI Responses |
|---|---|---|---|
| **累积键** | `delta.tool_calls[].index`（整型） | `content_block` 的 `index`（整型） | **`item_id`（字符串）**，index 由 `output_index` 另行映射 |
| **参数形态** | `function.arguments` 是 **JSON 字符串分片** | `delta.partial_json` 是字符串分片；非流式 `input` 是**对象** | `response.function_call_arguments.delta` |
| **id/name 到达时机** | 可能在**后续帧**才补齐 | `content_block_start` 一次给全 | item 上带 |
| **收口信号** | 整轮结束 | `content_block_stop` | `arguments.done` + `output_item.done` + `response.completed` **三条路径都可能给完整参数** |
| **终局校验** | **id 必须非空**，否则算协议错误 | 空参数补发 `"{}"` | 按 `item_id` 去重 |
| **并发** | 并发 map + 「非空才覆盖」 | 按块累积的 builder | 单线程状态机 |

**三条铁律**：

1. **`arguments` 绝不能 `parse` 再 `re-serialize`** —— 直接做字符串拼接。否则丢 key 顺序、丢空格、破坏大数字精度（会让模型看到的和自己写的不一致）。
2. **`id`/`name` 每次都用「非空才覆盖」语义**，不能直接赋值（OpenAI 兼容网关常在中间帧发空串）。
3. ⚠️ **`partialArguments` 这个字段有两种语义**：OpenAI 侧传的是**累积后的全量快照**，Responses 侧传的是**本次增量 delta**。Zig 里必须显式区分成两个不同的字段名，不要沿用同一个名字。

## C. Anthropic thinking —— 漏一个字段就 400（`anthropic.zig`）

- `content_block.type == "thinking"` 的响应块含 `thinking` **和 `signature`**；
- 还有 `redacted_thinking` 类型；
- **下一轮请求必须把 `signature` / `redacted_thinking` 原样回传**（作为消息的附加属性持久化，回传时再与 thinking 文本一起拼回）。

> **签名错位或丢失 → Anthropic 直接 400。** Zig 侧必须把 `signature` 作为**一等公民随消息全程携带**，不能只存 thinking 文本。

同理 Responses 的 `encrypted_reasoning` 需要跨轮回放（存 attributes → 经 `TurnCompleteEvent` 进会话 → 下轮回填）。

**另一个坑**：`returnThinking`（解析）与 `sendThinking`（下发）是**两个独立开关**，`thinkingFieldName` 默认 `"reasoning_content"` 可按厂商改。别只做一个 bool。

**请求侧下发形态也不同**：

| 场景 | 字段 |||
|---|---|||
| OpenAI | `reasoning_effort` |||
| Anthropic | 顶层 `thinking:{type:enabled\|
| DashScope（百炼） | 换成 `enable_thinking` + `thinking_budget`（按 host 判定） |||
| MiniMax | `model.startsWith("minimax/")` 时**不改** `thinking` |||
| Responses | `text_verbosity` |||
| Chat | `verbosity` |||

## D. token 计数 —— 四家四种口径，重复计数是静默 bug

- **OpenAI**：`prompt_tokens` **已包含** `prompt_tokens_details.cached_tokens`；本项目的 `Usage` 里 `inputTokens` 与 `cacheReadTokens` **互斥**（总量 = input + output + cacheRead + cacheCreation）
  → **必须 `uncachedInput = max(0, prompt_tokens − cached_tokens)`**。
- **DeepSeek**：缓存命中在**顶层** `prompt_cache_hit_tokens`，**不在** `prompt_tokens_details`。
- **Anthropic**：原生 Claude 的 `input_tokens` **不含** cache read；但**兼容网关常返回包含 cache read 的 inclusive 值**
  → 需按 `model.contains("claude")` 判定是否要相减。
- **cache 字段有 4 个**：`cache_read_input_tokens`、`cache_creation_input_tokens`、`cache_creation_input_tokens_5m`、`cache_creation_input_tokens_1h`。

**Zig 坑**：`u64` 减法前必须 `max(0, …)`，网关返回负值/缺字段很常见。

> 附：**不要引入 BPE** —— 本地 token 估算用 `char/4 × 4/3` 启发式即可（BPE 分词历史上引入过却 **0 处使用**，是死依赖）。

## E. 请求形状 / URL 归一化

- **`baseUrl` 尾斜杠**：官方文档明写「OpenAI 兼容端点必须以 **`/v1/`（带结尾斜杠）** 结尾，否则路径解析会吃掉 `/v1` → 404」。OpenAI 与 Anthropic 侧是**两套归一化规则**，且**历史出过事故**。
- **Anthropic 端点**：`baseUrl` 常以 `…/anthropic` 结尾，client 再补 `/v1/messages`；默认 `https://api.anthropic.com/v1/`。**同一 `type` 下 baseUrl 语义不统一。**
- **消息里夹 system 会被 400** —— **只有引擎注入的后台通知**（正文含 `<not_user_input>true</not_user_input>`）才渲染成 user 轮，其余 SYSTEM **不进 wire**。
- **Anthropic 的 tool_result 必须合并进一个 user 轮**（连续的 tool_result 累积后作为**一个** user 消息发出），否则触发 user/assistant 交替校验。
- **自定义参数透传会与 typed setter 撞车** → 会序列化出重复顶层 key（必须专门去重）。
- ⚠️ **`topLevelErrorEnvelope`**：某些兼容端点是 **HTTP 200 但 body 里有 `error` 字段**。只按状态码判成败会**静默拿到空回复**。同类还有各家的 `refusal` 字段（应抛 `ContentFilteredException`）。
- 兼容补丁（要实现）：`normalizeNullableAnyOf`（把 `anyOf:[{type:T},{type:null}]` 改写成 `{"type":[T,"null"]}`，62 行）、DeepSeek cache 兜底、`DEFAULT_USER_AGENT = "opencode/v1.15.5"`（硬编码冒充）、`ZIGENT_EXTRA_BODY` 环境变量透传。

## F. 流式重试的唯一闸门

- **`emittedOnAttempt`**：一旦本次尝试已向用户吐过**非 Error 事件**，就**禁止重试**（否则重复输出已流出的 token）。
- **心跳不算 emit**（要与 `StreamEventQueue.touch()` 的心跳区分开）。
- 退避优先级：**`Retry-After` 响应头 > 异常携带的 retryAfter > 本地退避**。
- 生产只用 `DEFAULT(3, 1s, ×2.0, cap 30s, jitter 0)`；`ROBUST`/`PERSISTENT` 是**死配置**（且无 config 绑定）。

## G. `tool_use` / `tool_result` 是「**紧邻**」配对

> 不是「会话里存在对应 id 就算配对」。

**定义**：**assistant 消息中的每个 `tool_use`，必须在紧邻的下一条 user 消息里集齐应答；反向，任何 `tool_result` 必须能对上前一条 assistant 的 `tool_use`。**

用运行期补丁守这个不变量，曾被写成 **6 处独立实现 + 3 套不同文案**（这本身就是债）：

1. 入转录前消毒畸形 JSON
2. 截断探测
3. 请求前守卫（就地修复）
4. load 侧守卫
5. 持久化失败后修复相邻配对
6. 补发缺失的 tool_result 块 ×2（结束轮 / 处理 API 错误）

**Zig 设计要求：把「assistant(tool_use) + 紧邻 user(tool_result)」做成不可分割的原子写入单元**（先构造完整对，再一次落盘），而不是事后再补。

算法:      AES-256-GCM
KDF:       PBKDF2WithHmacSHA256, 120_000 rounds, 256-bit output
SALT:      16 字节【硬编码】

## J. transcript 是混合事件日志，不是纯对话

```
~/.zigent/projects/<encoded-cwd>/transcripts/<sessionId>.jsonl
每行: Entry{uuid, parentUuid, type, sessionId, timestamp, message, metadata}
```

- **对话链靠 `parentUuid` 链表重建，不靠行序**；`latestLeaf` → 沿 parentUuid 回溯（去环）→ reverse。
- `type` 分流：参与对话链 = `message` / `compact_boundary` / `replay`；**不参与**（写同一文件但重建时跳过）= `tombstone` / `stop_metadata` / `inference_*` / `tool_*` / `error` / `retry` / `session_*` / `agent_*` / `file_*`。
- 重建时 `repairMessages` 剔除**孤儿 tool_result**（保证送进模型的历史永远配对）。

**魔法元数据串是恢复路径的判据**（不能改名）：
`invoked_skills`、`task_ledger`、`compact_continuation`、`user_skill_slash`、`recovery_hint`、`critical_reminder`、`agent_notification`、`user_interrupt`。

**三套时间戳键名都要认**：`timestamp` / `createdAt` / `created_at`。

> 若 Zig 换 schema，**既有用户会话将无法 resume / fork / 续压**。所以第一道验收门槛是「旧 transcript 逐字节 round-trip」。

## L. ⚠️ **不可信的旧文档清单** —— 已实测过期

这是实现时最容易踩的元级陷阱：**一批旧设计文档有多处与实际行为不符**，照文档实现会做错。

| 文档说法 | 实际行为 |
|---|---|
| `AUTOCOMPACT_BUFFER_TOKENS = 13_000` | **`40_000`**，且可被 env `AGENT_AUTOCOMPACT_BUFFER_TOKENS` 覆盖；余量公式是 `min(40_000, ceiling × 0.25)` |
| `PayloadStore`，`MAX_INLINE_BYTES = 4096`，payload 外置落盘 | **该类不存在**。全仓 0 文件、0 引用；`payloadRef` 字段存在但**所有生产构造点传 null** |
| `RecoveryAction` 11 种 | **13 种**（多出 `REPAIR_AND_RETRY`、`CLAMP_MAX_TOKENS_AND_RETRY`）；矩阵是 `16 × 13` |
| `PermissionMode` 有 `AUTO`/`ALLOW_ALL`/`DENY_ALL` | **代码里不存在**，只有 4 值；ACP 也只暴露 4 个 |
| `FilesystemGuard` 是生效的文件系统守卫，且已做符号链接检查 | **死代码**（main 0 引用，仅测试引用）；实际守卫是 `FileAccessGuard` + `PathValidator` + `FileSafetyGuard` |
| `session/set_model`/`resume`/`fork` 未实现 | **三者都已注册** |
| 「53 个子命令」「119 个 handler」「15 个 ACP serve 命令」 | 分别是 **44** / **216 条路由** / **12**（详见 `2026-09-19-14-CLI与命令清单.md`） |
| `/login`、`/logout` 是命令 | **只存在于帮助文档**，代码里没有 |

**纪律**：
1. **契约只从代码读，不从文档读**（文档用来找线索，代码用来定事实）；
2. 复核本文件里的每条约束时，**以实际行为为准**，不要照抄旧文档的转述；
3. 发现新的「文档 vs 实际行为」不一致，**追加到本表**（这是最有价值的交接物之一）；
4. 实现时**不要**顺手去改这些旧文档 —— 改了会混淆"设计意图 vs 实现事实"的边界。

## N. Zig 0.16 实测坑（2026-09-19 实现期新发现，**逐条都是真实编译/运行错误**）

> 这一节是 spike 之后、正式实现在 `src/` 上跑通时新增的。每条都给出**症状**与**正确写法**。

### N.1 `Io.Reader.readAlloc` / `readSliceShort` 会**读到缓冲填满或 EOF 才返回**

| 项 | 内容 |
|---|---|
| 症状 | 手写 HTTP 服务在 `curl` 下**永久挂起**：TCP 连上了，但一个字节的响应都不回 |
| 根因 | `readSliceShort(buf[0..4096])` 的语义是"填满 4096 字节才返回"；HTTP 客户端发完 header 后会**等响应** → 死锁 |
| 正确写法 | 直接走 vtable 读一次：`var d: [1][]u8 = .{buf}; iface.vtable.readVec(iface, &d)`，把 `error.EndOfStream` 映射成 `0` |
| 推论 | **任何"边上协议边等对端"的解析都不能用 `readSliceShort`**（HTTP/1.1、JSON-RPC 的交互式半双工都是这一类） |

### N.2 `stream.reader(io, &.{})` 传空缓冲 → 直接被当成 EOF

| 项 | 内容 |
|---|---|
| 症状 | 同上（挂起），且**与 N.1 叠加**，极易误判成"网络层没工作" |
| 正确写法 | 必须给一个真实缓冲：`var buf: [4096]u8 = undefined; var r = stream.reader(io, &buf);` |
| 注意 | Writer 同理；且**缓冲必须由调用方持有**（Writer 只存切片指针），所以 `SseWriter` 的缓冲要在 `streamEvents` 的栈上 |

### N.3 `std.process.currentPathAlloc` 返回 `[:0]u8`，调用方 `free` 会尺寸不匹配

| 项 | 内容 |
|---|---|
| 症状 | `error(DebugAllocator): Allocation size 24 bytes does not match free size 23` |
| 根因 | 它内部 `dupeZ` 分配 `len+1`；转成 `[]u8` 后 `free` 只释放 `len` |
| 正确写法 | `var buf: [max_path_bytes]u8 = undefined; const n = try std.process.currentPath(io, &buf); return gpa.dupe(u8, buf[0..n]);` |

### N.4 `ArrayListUnmanaged(T)` 没有 `.writer()`

`out.writer(gpa).print(...)` 编译失败；正确写法是 `out.print(gpa, fmt, args)`。

### N.5 `std.Io.net` **没有 `getsockname`**（0.16）

端口写 `0` 之后**无法**从内核问回真实端口。当前做法是在 49152–65535 随机试绑并把候选端口当成真实端口回报（契约目的不变，替换点只有 `util/io.zig::listenLoopback` 一处）。

### N.6 `Io.File` 既没有 `seekTo` 也没有 append 打开模式

追加写要用**定位写**：`file.writePositionalAll(io, bytes, try file.length(io))`。

### N.7 其它零碎（已踩过并修正）

| 症状 | 正确写法 |
|---|---|
| `std.mem.trimLeft/trimRight` 不存在 | `trimStart` / `trimEnd` |
| `Io.Clock.monotonic` 不存在 | `.awake`（单调）/ `.real`（墙钟） |
| `Io.Timeout.duration` 要 `Clock.Duration` | `.{ .raw = Io.Duration.fromMilliseconds(ms), .clock = .awake }` |
| `std.unicode.utf8Encode` 返回值是 `!u3` | 用 `tmp[0..n]` 切片 |
| `next_mtime` 的 `Stat.mtime` 是 `Io.Timestamp` | 直接 `.toMilliseconds()`，不要 switch |
| 结构体里字段与函数交错声明 | **所有字段必须在任何函数之前**（`declarations are not allowed between container fields`） |
| `fn init(...) PairingError!Turn` 内部 `try gpa.dupe(...)` | error set 必须显式并入 `Allocator.Error` |

### N.8 关键字撞名（改**内部标识符**，不改 wire 名）

| 想用的名字 | 冲突 | 落地命名 | wire 名 |
|---|---|---|---|
| `inline`（图片来源变体） | Zig 关键字 | `inline_data` | `data` |
| `defer`（权限裁决） | Zig 关键字 | `deferred` | `defer` |
| `error`（transcript 条目类型） | Zig 关键字 | `err` | `error` |
| `resume`（CLI 选项） | Zig 关键字 | `resume_session` | `--resume` |
| `error_event`（事件 tag） | 关键字 + wire 要求 | `error_event` | `error` |

### N.9 `std.mem.trimStart(s, "/api/session/")` **不是前缀剥离**

它按**字符集合**剥离：`/api/session/sess-1/prompt` 会被削成 `-1/prompt`（因为 `s`/`e`/`/`/`a`/`p`/`i` 都在集合里）。
路由解析必须用 `std.mem.startsWith` + 切片。
